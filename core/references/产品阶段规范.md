# 产品方案阶段规范

## 目标

描述用户和运营人员如何使用方案，不提前锁定内部技术实现细节。

## 产品方案文档

采用 `assets/02 产品方案.md` 模板，包含：

- 方案摘要和原则；
- 目标用户及场景；
- 信息架构或业务导航；
- 主流程和分支流程；
- 与需求编号对应的功能行为；
- 业务规则和校验；
- 加载、空数据、成功、部分成功、错误和恢复状态；
- 角色和权限；
- 适用时的通知与文案行为；
- 埋点事件和成功衡量方式；
- 兼容性与无障碍要求；
- 发布范围、延期范围和依赖。

使用 `FLOW-###`、`RULE-###`、`EVT-###` 编号。重复状态行为和映射优先用表格表达。

## 产品确认质量要求

- 每个 `REQ-F-###` 已覆盖，或明确说明不采用的原因；
- 每个主要场景都能由用户端到端完成；
- 适用时明确失败、重试、取消和重复操作行为；
- 权限与数据可见性差异明确；
- 不阅读技术方案也能验证产品方案。
