# 发布与复盘阶段规范

## 发布就绪

采用 `assets/12 发布检查单.md`，包含：

- 已批准范围和需求覆盖；
- 开发构建与自测、代码审查及独立测试证据；
- 未解决发现和已接受风险；
- 配置、秘钥和基础设施前置条件；
- 数据库或数据迁移顺序；
- 部署、冒烟和监控步骤；
- 回滚触发条件与过程；
- 负责人和沟通需求。

准备发布计划不代表授权部署、合并、发布、生产写入或外部消息；只有用户明确要求时才执行。

## 复盘

有实质性交付后，采用 `assets/13 项目复盘.md`，记录：

- 结果与证据；
- 可避免的澄清和返工；
- 遗漏或晚发现的需求；
- 哪些检查发现了缺陷，哪些检查未能发现；
- 缺失、冗余或含糊的模板章节；
- 窄范围改进建议及修改前后措辞；
- 可复用经验与项目专属经验的区别。

未经用户明确批准，不根据单个项目复盘自动更新公共技能。优先采用重复证据或明确高影响失败支持的改动。
