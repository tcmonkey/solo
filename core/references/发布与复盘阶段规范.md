# Release and retrospective standard

## Release readiness

Adapt `assets/12 发布检查单.md`. Include:

- approved scope and requirement coverage;
- development build/self-test, code-review and independent-test evidence;
- unresolved findings and accepted risks;
- configuration, secret and infrastructure prerequisites;
- database or data migration order;
- deployment, smoke test and monitoring steps;
- rollback trigger and procedure;
- owner and communication needs.

Preparing a release plan does not authorize deployment, merge, publishing, production writes or external messages. Perform those only when explicitly requested.

## Retrospective

Adapt `assets/13 项目复盘.md` after a meaningful delivery. Capture:

- outcome and evidence;
- avoidable clarification or rework;
- requirements missed or discovered late;
- checks that caught defects and checks that failed to;
- template sections that were missing, redundant or ambiguous;
- proposed narrow changes with before/after wording;
- reusable learning versus project-specific learning.

Do not update the shared skill from one project's retrospective without explicit user approval. Prefer changes supported by repeated evidence or a clear high-impact failure.
