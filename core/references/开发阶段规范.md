# 开发与开发自测阶段规范

## 修改前

- 确认技术方案已批准，或用户明确要求实施；
- 检查仓库状态，保留用户无关改动；
- 阅读项目指令、开发计划和实际待修改文件；
- 核对计划与当前代码，仓库证据推翻假设时更新计划。

## 编码规则

- 以最小且完整的改动满足已批准需求；
- 遵循已有架构、命名、格式和依赖规则；
- Java DDD 项目采用 `assets/java-ddd/reference-project/` 快照作为实现示例。阅读其 README 和计划选定链路，实施前检查相关 Controller/assembler、Application、DomainService/模型、仓储或 OutAdaptor/converter 及错误处理。生成真实业务名称、模型与逻辑，不复制全部演示链路。冲突时以规范与已确认决策为准；不依赖机器上的 workspace/ddd 绝对路径，不从业务项目自动反写公共快照；
- 使用已批准的 `ddd` 模板时，编码前阅读 [Java DDD开发规范](Java%20DDD开发规范.md)，历史只作证据。创建 Maven 聚合根后、正式编码前，自动执行 `scripts/install_java_ddd_checks.py --project <project-root>`，安装根 checkstyle.xml、继承的 validate/check 门禁和编号本地规范副本。这是模板初始化步骤，不另设确认关口。保留已有冲突配置并明确协调，不强加给无关技术栈；宿主无法执行时，根据 assets/java-ddd 生成等价文件，并说明未执行检查；
- 方案采用 Maven/Gradle 模块时，源码与测试放入所属模块，只声明允许的编译依赖，从聚合根执行完整构建。新模块目录和 artifactId 保留 `<project-name>-<layer>` 命名，不为实现方便将模块折叠成 package；
- 不添加无依据的抽象或无关清理；
- Java DDD 模板的 start POM 是本服务显式装配清单，直接声明实际运行的内部模块，不只依靠传递依赖。完整示例包含其余七个模块；真实项目裁剪无用途、工具专用和其他服务模块。测试专用依赖使用 test scope，版本由根管理。审查有效依赖树，验证完整构建与启动路径；Checkstyle 不检查该 POM 规则；
- 秘钥、凭据和个人数据不得进入代码、日志或生成产物；
- 本模板的 Maven 3 同版本模块，默认项目版本只在根 properties/revision 定义，根 version 与子模块 parent.version 使用 ${revision}，根管理内部依赖仍使用 ${project.version}。继承根 Flatten 插件（resolveCiFriendliesOnly、updatePomFile=true，绑定 process-resources/clean），忽略生成的 .flattened-pom.xml，不纳入快照。验证默认、命令行覆盖版本构建及安装后在源码聚合工程之外的消费；未经授权和实际执行，不声称已远程发布；
- 在系统边界明确错误、校验、授权和可观测性；
- 数据结构与契约变更须兼容，或明确迁移和回滚；
- 按风险为业务规则、边界和回归增加有意义的自动测试；
- 将示例测试调整为真实验收条件；根据获批生产方案替换 H2、外部模拟响应、演示 schema 和固定平台版本。明确剩余演示配置，不声称参考快照已经满足生产要求；
- 行为变化时更新使用说明或运维文档。

完成工作时更新 `05 开发计划.md` 任务状态及 `14 交付追踪矩阵.md`。发现需求或设计缺陷时，暂停受影响路径，记录证据、修订上游文档，并将依赖项标为待重新验证。

## 开发自测

声明可进入代码审查前，执行仓库具备且适用的检查：

1. 编译、构建或类型检查；
2. 静态检查和格式检查；
3. 变更业务规则与边界的单元测试；
4. 开发侧专项模块、契约或集成检查；
5. 变更路径的最小冒烟检查。

在 `06 开发自测报告.md` 记录准确命令、退出状态、证据和局限。不可用、跳过和失败不能混为通过。开发自测证明实现就绪，不等同独立产品验收。

## 开发就绪关口

只有以下条件满足，阶段才能成为 `complete`：

- 计划任务已完成或明确延期；
- 代码与相关文档已更新；
- 适用自测通过，或剩余失败明确记录为阻塞项；
- 已记录变更文件、完成任务编号、主动偏离及已知缺口；
- 实现具备进入独立代码审查的条件。

采用 `assets/06 开发自测报告.md` 记录检查点。
