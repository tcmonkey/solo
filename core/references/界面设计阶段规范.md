# UI and interaction standard

## When to enable

Enable for new screens, new navigation, material interaction changes, or when visual consistency cannot be derived from an existing design system. For existing components with minor copy or layout changes, capture the relevant states in the product document and skip this phase with a recorded reason.

## Inputs

Inspect screenshots, designs, brand assets, the current application, component libraries and responsive behavior when available. State when a visual decision lacks evidence.

## UI artifact

Adapt `assets/03 界面设计方案.md`. Include:

- screen inventory and hierarchy;
- annotated user flow;
- component and reuse mapping;
- content hierarchy and copy;
- interaction and transition behavior;
- loading, empty, success, error, disabled and permission states;
- validation messages;
- responsive breakpoints or adaptation rules;
- keyboard and accessibility behavior;
- visual references and unresolved design decisions.

Use `SCREEN-###` and `COMP-###`. Map screens to `FLOW-###` and requirements.

## Quality bar

The specification must be implementable and testable. Do not imply pixel-perfect fidelity without measurements or an authoritative design source.
